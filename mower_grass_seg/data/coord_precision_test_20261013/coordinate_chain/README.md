# 草坪分割坐标精度实验

2026-10-13，在同一批 50 张图片上比较两个独立 NPU 实验。原始静态和摄像头默认模型未替换，摄像头未启动。

## 结果

全部模型统一使用修正后的 floor/ceil 裁剪规则，以 PyTorch 输出为一致性参考，不是相对人工标注的准确率。

| 模型 | 平均 Mask IoU | 最低单图 IoU | 日志 inference 平均值 |
| --- | ---: | ---: | ---: |
| 当前混合精度 | 97.81% | 87.29% | 36.05 ms |
| 单独将 Mul_2 输出改为 FP16 | 98.03% | 87.72% | 35.99 ms |
| 坐标计算链 7 个节点改为 FP16 | 98.89% | 89.50% | 36.01 ms |

坐标计算链实验相对当前模型有 41 张改善、9 张下降。下降最大的是 011，约下降 0.87 个百分点；最低分仍是 044。没有预设验收阈值，不能仅凭均值宣告验收通过。

以上日志 inference 字段包含输入提交、推理与输出获取，不含 Mask 后处理。不同批次约 0.06 ms 的差别不应解读为确定的加速；本次未观察到明显增加，不代表正式摄像头端到端性能已验证。

## 截图对应的 009 图片

当前 NPU 框下边界为 475.75，单节点实验为 475.375，计算链实验为 479.125；ONNX 参考为 478.481，原图高度为 480。

使用同一修正后的裁剪规则，009 的 Mask IoU 从 96.40% 提升到 97.78%。计算链实验减少了底部被框裁掉的缺口，但并不是所有边界都与参考完全一致。只修改最后的 Mul_2 不足以解决这个样本的问题。

## 节点与验证

单节点实验只新增 `@model.22/Mul_2_output_0_6:out0` 为 FP16。

计算链实验新增以下 7 个节点为 FP16，既有最终拼接 FP16 保持不变：

```text
@model.22/Mul_2_output_0_6:out0
@model.22/Concat_5_output_0_11:out0
@model.22/Div_1_output_0_18:out0
@model.22/Sub_1_output_0_19:out0
@model.22/Add_2_output_0_24:out0
@model.22/Add_1_output_0_26:out0
@model.22/Sub_output_0_27:out0
```

均从原始导入模型出发，使用相同 100 张校准图片、相同前后处理配置重新执行 hybrid 校准及 NB 转换。校准后的量化表与基线比较，分别只有预定的 1 项和 7 项发生变化。两组均完成真实开发板 50 张推理，输出文件与板端 SHA256 核对通过。

两组实验的类别分数、Mask 系数、Mask 原型输出在 50 张图上均与基线逐值一致。框坐标变化仍可能影响 NMS 选择及最终 Mask，不能据此推断所有掩码都只存在平移。
