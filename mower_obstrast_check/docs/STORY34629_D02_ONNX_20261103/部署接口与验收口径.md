# D02 独立 AM970 开发板部署接口与验收口径

对应 STORY #34629，2026-11-03。范围为 D02 ONNX 导出、软件一致性验证和独立开发板部署接口确认。公司项目接入、D02 NPU 转换及 ROS2 检测跟踪节点实现不在本次已完成结果中。

## 1. 模型及输入输出

- 权重：本目录 `best.pt`，来自已冻结的 D02。YOLOv8n + P3 通道注意力，P3/P4/P5 检测头，无 P2。
- 类别：0 person（人员）、1 cat（猫）、2 dog（狗）、3 frisbee（飞盘）、4 sports ball（运动球）、5 teddy bear（玩具熊）、6 garden hose（软管）、7 rock（石块）。不得使用原十二类中的软管 10、石块 11。
- ONNX：`best.onnx`，opset 12，FP32，静态 batch=1，输入 `images[1,3,640,640]`，输出 `output0[1,12,8400]`，不包含 NMS。
- 输入处理：图像等比例缩放、居中 letterbox 至 640×640，填充值 114；BGR 转 RGB；HWC 转 NCHW；float32 除以 255。禁止直接拉伸图像，禁止重复归一化。
- 输出前四个通道是输入平面上的 cx、cy、w、h，后八个通道是类别分数；不另乘 objectness，不再次做 sigmoid。每候选取最大类别分数。
- 筛选：conf=0.25，按类别 NMS，IoU=0.70，max_det=300，multi_label=false。NMS 后去掉 letterbox 填充、除缩放比例，裁剪到原始图像边界。
- 二维框采用原图像素浮点 xyxy；左上角为原点，x 向右、y 向下。转中心框时 center=(x1+x2,y1+y2)/2，size=(x2-x1,y2-y1)。不将二维框解释为米制位置或距离。

**与历史评估的区别：**此前选型采用 rect=true；固定尺寸 ONNX 使用 640×640 方形补边。本次 PT 与 ONNX 共用同一输入张量及后处理。此处结果用于判断转换一致性，不替换历史验证集 AP，也不把输入补边差异算作量化误差。

## 3. 芯片转换与代码复用边界

本地 WSL 已有 Acuity 6.33.31、VivanteIDE 5.10.1 和 VKNN 示例。已有转换脚本使用 VIP9000NANODI_PLUS_PID0X1000000B 目标；下一任务应以实际 D02 编译成功、板上加载及全样本对比为最终兼容性证据。

- ONNX 是转换中间格式；板端 VKNN 路线加载 NBG `.nb`（通常命名 `network_binary.nb`），不能把 ONNX 改后缀当作 NPU 模型。
- 可复用本地 `/root/cpp_project/am970/model/scripts` 的 Acuity 转换流程，以及 `/root/cpp_project/am970/vknn_demo_yhc` 的模型初始化、输入、推理、输出和释放流程。
- VKNN API 主链为 `vknn_init → vknn_process_input → vknn_inference → vknn_process_output → vknn_release`。SDK 缓冲区 size 字段按元素数填写，不能未经检查按字节数填写。
- 分割模型的 37 通道输出和 mask 解码不适用于 D02；D02 是 12 通道单输出。分割模型的混合精度层名单也不能直接照搬。
- 转换时确认 mean/scale、通道顺序、NCHW/NHWC、输入 dtype 和输出量化参数。若预处理已嵌入 `.nb`，板端不能再执行相同归一化。
- 校准样本从训练集选取，覆盖八类及不同亮度、目标尺寸；固定验证集和 140 张测试集用于复评，不参与校准选样。
- 注意力相关 GlobalAveragePool、Mul、Sigmoid 等算子在 ONNX 中存在；尚未完成 D02 的 Acuity 导入，因此本次不承诺其量化兼容性和 NPU 性能。

## 4. ROS2 接入契约

以下为本任务确定的独立板节点设计约定，实际话题名允许参数或 remap 调整；公司系统的实际话题尚未对接。

| 接口 | 约定 |
| --- | --- |
| 图像输入 | `/camera/image_raw`，sensor_msgs/msg/Image，支持 bgr8/rgb8；按 step 读取，不假设行连续 |
| 检测输出 | `/obstacles/detections`，拟采用 vision_msgs/msg/Detection2DArray；先补齐并核对目标版本消息定义 |
| header | 复制输入图像的 stamp 与 frame_id，禁止用推理结束时间替代采集时间 |
| 类别/分数 | class_id 使用字符串形式的 0～7，score 为 0～1；类别映射随模型一起部署 |
| bbox | 原图像素中心坐标及宽高；图像尺度发生变化时同步更新，不能发布 640 补边平面的框 |
| 无目标 | 成功处理当前图像后发布带原图 header 的空检测数组 |
| 跟踪信息 | 后续 ByteTrack 才生成 track_id、状态及轨迹；本次不伪造 ID，也不把检测序号当轨迹 ID |
| 错误状态 | 输入中断/推理失败通过诊断状态发布，不能冒充“处理成功且无障碍物” |
| 排队策略 | 输入 QoS best_effort、volatile、keep_last=1；工作线程只保留最新待处理帧；输出使用同类低积压配置，联调核对订阅端 QoS |
| 延迟统计 | 本机阶段耗时使用单调时钟；跨设备端到端延迟需要已同步的采集时间，板上 1970 时间现状不满足这一前提 |

本次仅确定字段语义和依赖；消息包构建、节点发布、ByteTrack 和相机断流联调在后续任务完成。图像 frame_id 不等于机器人底盘坐标系；二维检测本身不提供避障距离。

## 5. 验收口径

### 本次 PT/ONNX 转换一致性

采用同一批图像、同一个预处理数组和相同 NMS。按同类别 IoU≥0.5 做一对一框匹配，再检查严格数值误差；IoU≥0.5 仅用于配对，不作为数值一致性的放宽条件。

| 指标 | 本次检查阈值 |
| --- | --- |
| 输出 | shape 相同，全部为有限值 |
| 原始候选框通道最大绝对误差 | ≤0.01 输入像素 |
| 原始分类分数最大绝对误差 | ≤0.0001 |
| NMS 后未配对框 | 0 |
| 配对框原图最大坐标误差 | ≤0.1 像素 |
| 配对框置信度误差 | ≤0.0001 |

所有异常逐图保留，不能因个别图可运行就判定通过。实际测量见交付报告及 comparison/summary.json。

### 后续 NPU 与 ROS2 工程验收建议

以下是后续测试的暂定工程门槛，**不是已经测得的板端结果，也不是已确认的整机业务指标**：

1. 精度：固定完整验证集，imgsz=640、相同补边、相同后处理，评估 AP 时 conf=0.001；NPU 相对本次 ONNX 的 AP50-95 下降不超过 1 个百分点。另以 conf=0.25、IoU 匹配阈值 0.5 统计八类 P/R 和人员、动物、小目标召回，人员及动物召回下降不超过 2 个百分点。小目标沿用选型报告尺寸口径，不临时改变定义。样本少的类别同时列 TP/FP/FN。
2. 性能：batch=1，640 输入，记录预处理/NPU/后处理/发布耗时及总耗时 P50/P95；预热至少 50 帧、正式至少 1000 帧。先以持续处理 ≥10 FPS、帧被节点接收至发布 P95≤150 ms 为独立板工程目标，实测后再与整机预算确认。
3. 稳定性：连续运行至少 1 小时；记录输入、处理、丢弃、发布计数和 RSS。最多保留一帧待处理数据，不随时间积压；预热后内存不能持续单调增长，比较首末 10 分钟 RSS 中位数，增长不超过 10 MiB，并保留时间序列确认是否已稳定。
4. 接口：逐帧核对 header；使用非 640 原始图片验证框还原；测试空帧、无目标、相机断流与恢复；未处理旧帧不得重贴新时间戳发布。
5. NPU 量化不达标时记录失败样本和误差，定位输入处理、输出反量化、敏感层或后处理；是否采用混合精度由新对比证据决定。
